# 2026-11-06 0.6B 工人日期补训（SFT20b/SFT20c）

> 目标：修 SFT20 工人「下周X」算错（周五说「下周一」→ 11-07）。数据生成、训练、评测全记录。

## 1. 数据

### 1.1 规则生成（SFT20b）
- 脚本：`train/synthesize/gen_date_worker.py`，用 `datetime` 规则算目标，不调教师。
- 规模：4000 条（日历 2400 / 提醒 1600）+ 回放 800（translate 300 / summary 300 / calendar 100 / reminder 100，来自 `cloud_sft20/worker_sft20.jsonl`）= 4800，train 4704 / val 96。
- 覆盖：今天/明天/后天/大后天/N天后；这周X/本周X/下周X/下下周X（周一至周日全）；M月D日/号、下个月D号；早上/上午/中午/下午/傍晚/晚上/凌晨 + 整点/半/一刻/三刻/X分；今晚/明早/明晚；时长 15/30/45/60/90/120/150/180 分钟；跨月/跨年/闰日/跨午夜。
- 周约定：本周 = ISO 周（周一起），下周 = 下一个 ISO 周；本周只生成今天及以后。
- 独立 QC：`train/synthesize/qc_date_worker.py` 从用户话术反解日期，3924 条 train + 76 条 val 全对（0 错误）；评测集 60 题全对。

### 1.2 加日期表（SFT20c）
- 脚本：`train/synthesize/add_date_table.py`。
- 给日历/提醒样本追加三周日期表：`日期参考：本周周一=…；下周周一=…；下下周周一=…。`（21 个日期，YYYY-MM-DD）。
- translate/summary 不加表（生产也不会加）。
- 过采样：translate/summary 各 882/870（原 300 各，3 倍），防日期样本占 8 成把摘要格式带崩。
- 最终 train 5872（calendar 2453 / reminder 1667 / translate 882 / summary 870；rule 3924 / replay 1948），val 96。

## 4. 关键坑

1. **日期表必须进训练分布**：零样本把表追加到提示词，SFT20b emit 1/60，模型复读整段输入。SFT20c 用 4200 条带表样本训练后才学会抄表。
2. **`--no-think` 模型推理端必须 `enable_thinking=false`**：llama-server 只加 `--jinja` 不注入空思考块；SFT20c 首次评测 1/60，表现为复读输入/聊天确认，原始 HF checkpoint 直接推理却完全正确。加 `--chat-template-kwargs '{"enable_thinking": false}'` 后恢复正常。此前 SFT20/SFT20b 的回归失分（7/8、6/8）也是同一原因，补上后三版都 8/8。
3. 0.6B 不会星期心算：SFT20b 4000 条、loss 0.01，下周X 仍 2/22；查表是容量内可行解。

## 7. 结论

采用 SFT20c Q5 作为工人模型。**引擎必须**：① 派单给日历/提醒工人时追加三周日期表；② 所有 SFT20 系模型推理注入空 `<think></think>` 块。缺一即退化。
