# 上下文记忆与调度赛道调研（2026-11-10）

> 目的：判断「上下文参数化 + 外接记忆库 + 小模型管理生命周期 + 每轮路由」这个想法能不能做成论文/产品。
> 方法：GitHub 星标与仓库、arXiv 摘要（能直接核的已核）、2026 年公开报道。厂商自测数字均标注「厂商口径」。

## 0. 一句话结论

这个方向在 2026 年已经从「想法」变成「赛道」：四个要素都有已发表或已开源的实现，概念层面没有空白。**唯一还没人做的，是「主模型和记忆管理器都是 <2B、同时装在一台手机上」这个资源约束下的版本**——MemSifter 的代理模型是 4B 且在云端，MobileMem 只做评测不做策略，mzCache 只管 KV 不管语义记忆。

## 1. 你的四个要素，各被谁占了

| 你的表述 | 已有工作 | 结论 |
|---|---|---|
| 把上下文参数化，挂到外接库 | MemOS 的 MemCube：统一封装文本、激活态（KV）、参数补丁（LoRA）三种记忆载荷，配 MemScheduler 调度（arXiv 2507.03724） | 已被完整定义 |

## 2. 学术地图（五条线）

### 2.1 记忆系统/记忆 OS
- **MemGPT / Letta**：操作系统式分层上下文，Agent 自己决定读写。2026 年仍是基线。
- **MemOS**：MemCube 抽象 + MemScheduler，明确把记忆当系统资源调度；记忆张量公司开源，2026-05 星标 1.2 万，厂商口径称时序推理比 OpenAI 内置记忆高 159%。
- **MemoryOS**（arXiv 2506.06326）：借操作系统分页思想做短/中/长期分层，常被当评测基线。
- **A-MEM**（NeurIPS 2025）：Zettelkasten 式笔记网络，写入时自动建链、演化。
- **Mem0**（arXiv 2504.19413）：生产级记忆层，抽取 + 合并 + 图变体；2026 年推出 Dream 后台整理（取代/合并/衰减）。
- **EverMemOS、MemX（本地优先）、Mnemis（微软，双路图检索）、MemTree**：细分路线仍在增加。

### 2.2 学习型记忆管理（最接近你的「小模型管理生命周期」）
- **AgeMem**（ACL 2026 SAC Highlight）：统一 LTM/STM，六类记忆工具进动作空间，三阶段渐进 RL + step-wise GRPO；媒体口径称三个基准提升 +13.9%/+21.7%/+16.1%。
- **Memory-R1**（ACL 2026）：ADD/UPDATE/DELETE/NOOP 四动作，outcome-based RL。
- **Mem-T**（arXiv 2601.23014）：记忆操作树 + MoT-GRPO。
- **UMA / Learning to Remember**（arXiv 2602.18493）：端到端记忆 agent + CRUD + Ledger-QA。
- 趋势判断：记忆管理正从「启发式规则」转向「可训练策略」，这是 2026 年的主线。

### 2.3 小模型代理检索（最接近你的「每轮路由」）
- **MemSifter**（arXiv 2603.03379，已核摘要）：把检索外包给 4B 代理模型，先推理任务需要什么，再对候选会话排序；用工作模型的实际表现为奖励做 RL；索引阶段无重计算；开源权重与代码。
- **MemSifter 的意义**：它证明「小模型管记忆」成立，也意味着你的同类主张必须回答「比 4B 更小还行不行」，否则只是复现。

### 2.4 上下文压缩与 KV
- **GIST tokens / AutoCompressors**（2023）：把长历史压成几十个软向量，30 倍以上压缩。
- **ACON**（arXiv 2510.00615，已核摘要）：面向长程 agent 的观察与历史压缩，在自然语言空间迭代优化压缩准则。
- **IndexMem**（ICML 2026）：学习式 KV 驱逐 + 潜变量记忆，固定 KV 预算下保精度。
- **C²KV、DepthWeave-KV、RocketKV**：KV 压缩/复用，工程向。
- **context-mode**：MCP 层把工具大输出挡在窗口外，SQLite+FTS5 按需取回；2026-10 约 2.7 万星。
- 判断：这一层已经卷到「每个 token 的性价比」，不是新点子能站住的地方。

### 2.5 评测基准
- **LoCoMo**（ACL 2024）：10 段多会话对话、约 2000 题，五类能力（单跳/时序/多跳/开放/对抗）。
- **LongMemEval**：更长的多会话记忆评测，S 版 38–62 会话/样本。
- **BEAM、ConvoMem、MemoryArena、CloneMem**：2025–2026 陆续补位；MemoryArena 显示 LoCoMo 高分方案在决策任务上只有 40–60%。
- **MERIT**（2026-10）：指出 LoCoMo/LongMemEval 测的是「答历史题」，不是「记忆是否改变工具型 agent 的行为」，提出 cost-aware 评测。
- **MobileMem**（OPPO + OpenKG，ICLR 2026 Lifelong Agents Workshop）：**端侧**记忆评测基准，百万词元历史上下文，覆盖跨时间/跨应用/跨模态事件。这条最要命——它把「端侧记忆评测」这个坑先占了。

## 4. 端侧这条线现在到哪了

- **MobileMem**（评测）：端侧记忆能力基准，不提供策略。
- **mzCache**（2026-09 arXiv）：端侧 LLM 推理的内存管理，多任务下弹性驱逐权重/KV、统一内存恢复；系统层，不做语义记忆。
- **Samsung**（2026-09-30）：小模型做信号过滤、端侧 LLM 做深分析，「Right Context / Right Computation / Right Model」；工业架构，无论文数据。
- **MemX**：本地优先的长期记忆系统（arXiv 2026）。
- **AnythingLLM Mobile**：端侧小模型 + 内置记忆的产品化。
- **结论**：端侧「系统层」和「评测层」都有人了，**「语义记忆策略在真实手机预算下的取舍」还没有公开论文**。

## 5. 还剩的三个空白（按可做性排序）

### 空白 A：双小模型同机的记忆调度（最推荐）
现有小模型代理是 4B 且跑在云端（MemSifter）；端侧主模型通常 1–2B。**没有人回答：0.6B 的路由器 + 1.7B 的主模型，同时装进 2GB 内存，记忆调度还成不成立。**
- 可证伪问题：在固定 RAM/延迟预算下，「小模型路由」是否仍然优于「向量 top-k」和「规则记忆」？
- 需要的实验：LoCoMo/LongMemEval 子集 + MobileMem，四组策略对照，指标同时记准确率、首 token、峰值内存、注入 token。
- 成本：2–3 个月，2×5090 够用；需要先在引擎里加一个记忆模块。

### 空白 B：记忆策略 × 系统预算的联合评测
MERIT 做的是云端成本（美元/token），MobileMem 做的是能力，**没有人把「语义策略 × KV/上下文预算 × 热与电」放在一台真机上画 Pareto 曲线**。这是测量型贡献，不做新算法也能发 workshop。
- 成本：1–2 个月，复用现有真机跑分链路。
- 风险：贡献偏工程，顶会难，workshop/系统 track 合适。

### 空白 C：可审计、可删除的端侧记忆
行业报道明确指出「可『真删除』的记忆还没造出来」；记忆的写入条件、修正、删除、用户授权仍是治理空白。这与 AIY 命题「AI 出错谁确认」同源。
- 成本：3–4 个月，需要用户研究，HCI 门槛高。
- 结论：想法好，现在不做。

## 6. 三个选题与建议

| 选题 | 主张 | 周期 | 风险 | 适合投 |
|---|---|---|---|---|
| A. 0.6B 记忆路由 + 1.7B 主模型同机 | 「记忆管理器可以比 4B 更小，且端侧可行」 | 2–3 个月 | 中：结果可能是「规则更好」 | 边缘/端侧 workshop、arXiv |
| B. 真机记忆调度 Pareto 实测 | 「同一策略在手机上差多少内存和延迟」 | 1–2 个月 | 低：结果是数据，不容易被抢 | 系统/测量 workshop |
| C. 可审计记忆 | 「删除与确认能验证」 | 3–4 个月 | 高：需要用户研究 | HCI 会议 |

**建议顺序：先做 B 的数据，再决定要不要做 A。** B 的产物（记忆模块 + 真机指标 + 可视化）本身就能进 AIY 的「未来工作」，也为 A 提供基线；如果 B 发现小模型路由打不过向量检索，A 就直接停，省两个月。

## 7. 不建议做的事

- **不要现在写「参数化上下文」的论文**：MemOS 的 MemCube 已经把文本/KV/LoRA 三种载荷统一了；在手机上持久化 KV 和每用户 LoRA 都不现实，写出来会被问「你和 MemOS 的区别是什么」。
- **不要做通用记忆层产品**：Mem0/Letta/Zep/MemOS/腾讯/火山都在，资本和渠道都不在个人这边。
- **不要赶在 12-24 前投论文**：AIY 和申请季在前，论文最早 1 月后启动；workshop 截稿通常 2–5 月，来得及。
- **不要把厂商自测数字当基线**：同一 LongMemEval 名义下，不同 harness 能差几十分；引用时标「厂商口径」。
