二、项目是什么
────────────────────────
· 一句话：把 1.7B 的量化模型和一套工具执行层装进 iPhone，断网也能完成
  「听懂一句话 → 调手机工具 → 把结果写进日历」的完整闭环，数据不出设备。

八、我这次的具体任务
────────────────────────
任务：T1 首次安装体验（GitHub Issue #1）

目标
以「第一次拿到这个 App 的人」的身份，从安装开始走到第一次成功对话，记录每一步卡住的地方。
队长已在三台 iPhone 上跑过 16/16 功能回归，功能是通的，不用再验一遍。

前置条件
· 一台能装应用的 iPhone（自己的或借的），系统 ≥ iOS 16
· Wi-Fi 能下载约 3.1GB 模型；手机剩余空间 ≥ 8GB
· 全程不问我怎么做，卡住先记录

五步观察，每步记：用了多久 / 卡在哪 / 当时第一反应的原话 / 一张截图
1. 从收到安装邀请开始，把 App 装到桌面：邀请好不好找、有没有看不懂的步骤
2. 打开 App 等模型下载完：看不看得出要下载、进度在哪、切后台会不会重置
3. 走完权限弹窗（麦克风/日历/提醒事项）：看不看得懂为什么要、拒一个会怎样
4. 打开飞行模式，问一道数学题（例如 求 x²-5x+6=0 的根）：会不会以为要联网、结果对不对
5. 说「明天下午三点提醒我交作业」，再去日历确认：知不知道去哪看、时间对不对、失败有没有提示

交付物
· docs/aiy27/qa/首次安装体验-YYYYMMDD-张曜阳.md
· 截图放 docs/aiy27/qa/shots/，文件名用编号，例如 t1-02-模型下载.png
· 报告格式：表头写设备型号/系统版本/构建号；正文五步表格（步骤/耗时/卡在哪/第一反应/截图）；
  卡点详述（编号步骤，期望看到 vs 实际看到）；最后一句「如果只能改一处，改哪」

验收标准
· 五步每步都有结论和截图，没有跳过
· 每个卡点都有当时的原话，不是事后总结
· 设备型号、系统版本、构建号齐全
· 最后给出「如果只能改一处」的一句话判断
· 没有为了凑数编出来的问题

禁止
· 没实际装就填结果
· 让我或智能体代填结论
· 把队长的操作步骤当成自己的体验
