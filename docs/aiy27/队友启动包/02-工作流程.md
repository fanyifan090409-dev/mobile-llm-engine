# 02 · 工作流程

> 目标：让一件任务从「派下来」到「合进仓库」有固定路径，谁都不用猜。
> 全程只用浏览器，不装软件、不碰命令行。

---

## 1. 先认清地盘

| 目录 | 谁能改 | 内容 |
|---|---|---|
| `docs/aiy27/qa/` | 张曜阳、薛亦湘 | 走查报告、测试记录、访谈记录 |
| `docs/aiy27/demo/` | 薛亦湘 | 分镜脚本、数字核对表 |
| 其他所有目录 | 只有队长 | 引擎、App、训练、PPT、计划文档 |

**别人的目录不要动。** 需要改别人的文件，在 Issue 里说，让本人改。

## 2. 一件任务的五步

```
① 队长开 Issue（任务单）
        ↓
② 队员认领，在 Issue 里回一句「我接了」
        ↓
③ 队员在网页端建文件 / 改文件，提交时选「Create a new branch」
        ↓
④ 队员发起 PR，按模板填：关联任务 / 改了什么 / 证据 / AI 参与说明 / 自查
        ↓
⑤ 队长逐条对验收标准 → 打回或合并
```

被打回不用重开：直接在原来的 PR 上改，改完回一句「已修改，请再看一次」。

## 3. PR 必须带的四样

1. **关联任务**：`Closes #编号`
2. **证据**：截图文件名、原话记录、来源文件与具体位置——一条一行，对应验收标准
3. **AI 参与说明**：哪些是智能体起草的、哪些是你实测的。没有就写「无」
4. **自查**：三个勾都打。**没实际做的项不许打勾。**

## 4. AI 参与怎么说

- 用智能体整理、排版、查漏 —— 正常，写清楚就行
- 智能体替你产生测试结果 / 用户原话 —— **不可以**
- 由智能体起草比例高的提交，提交信息末尾加一行：`Assisted-by: <工具名>`

披露不转移责任：提交人仍然是唯一作者，要能解释每一句话。

## 5. 怎么把这份启动包喂给你的智能体

开场白、整理记录、改写卡点、提交前自检、被打回处理——五段现成的提示词在 [04-提示词](04-提示词.md)，直接复制粘贴，替换占位符即可。

用之前记住一条：**智能体负责结构、措辞、查漏；你负责事实、判断、签字。**

## 6. 卡住了怎么办

1. 先在 Issue 里写清楚：卡在哪一步、报什么错、试过什么
2. 超过 30 分钟没进展再找队长
3. **不要绕过流程**：不要自己合并 PR、不要改别人目录、不要为了让检查通过而删掉检查
