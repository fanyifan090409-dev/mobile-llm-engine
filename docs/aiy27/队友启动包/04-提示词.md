# 04 · 提示词（直接复制粘贴）

> 五个场景各一段，按顺序用。每段都留了 `【粘贴…】` 占位，替换成真实内容再发。
> 通用规矩：发给智能体的任何一段，都可以在最前面加这一句——

```
凡是材料里没有的数据、结论、用户原话，一律标【待补】，不许编造。
```

---

## ① 开工前：把背景喂进去

```
你是我的协作助手。下面是我们团队参加 AIY HACK LEAGUE 2026 的全部背景材料，请完整读完再回答。

【材料 1｜比赛要求与定位】
<粘贴 00-比赛要求与定位.md 全文>

【材料 2｜项目介绍与真实数据】
<粘贴 01-项目介绍与真实数据.md 全文>

【材料 3｜工作流程】
<粘贴 02-工作流程.md 全文>

【材料 4｜工作纪律】
<粘贴 03-工作纪律.md 全文>

【材料 5｜我的任务单】
<粘贴 GitHub Issue 正文>

先不要给建议。按顺序回答四个问题：
1. 这份任务的验收标准一共几条？逐条列出来。
2. 要交付什么文件、放在哪个目录？
3. 哪些证据必须由我本人产生、你没法代替？逐条列出。
4. 材料里有没有互相矛盾、或者你没看懂的地方？

回答完等我确认，再继续。
```

> 如果智能体说上下文太长：先只发材料 1、2 让它建立背景；动手时再发 3、4 和任务单。

## ② 执行中：把原始记录整理成报告

```
下面是我今天实际记录的内容，是原始版，没有整理过：
<粘贴备忘录 / 手写照片的转述 / 微信里的零散记录>

请按任务单要求的表格格式整理。规则：
1. 只整理，不许新增任何我没记录的事实
2. 我空着的列填【待补】，不要猜
3. 我的原话保留原样，不要润色成书面语
4. 整理完，最后单独列出「需要我补充的材料」清单

不要写「总的来说」这类总结段。
```

---

## ③ 执行中：把卡点改写成可复现步骤

```
下面是我遇到的一个问题，请改写成「别人照着能复现」的步骤：
<粘贴你的描述>

要求：
- 编号步骤，一步一个动作
- 每步写清「我期望看到什么」和「实际看到什么」
- 只描述现象，不要替我分析原因
- 如果信息不足，列出你还缺什么，不要自己补
```

---

## ④ 提交前：自检 + 生成 PR 描述

```
我要提交 PR 了。请对照任务单逐条检查我的材料，输出三块：

1. 验收标准对照表：每条 → 已覆盖 / 未覆盖 → 对应文中的哪一段或哪张截图
2. 缺口清单：还缺什么、需要我补什么（不要替我编内容）
3. PR 描述草稿，按模板分段：
   - 关联任务：Closes #<编号>
   - 这个 PR 改了什么：两三句
   - 证据：一行一个，只写我实际提供的文件名
   - AI 参与说明：哪部分由你起草、哪部分我实测
   - 自查：三条勾

最后再回答一个问题：如果我带着这份东西去答辩，最可能被问倒的是哪三个问题？
```

## ⑤ 被评审打回后

```
评审意见如下：
<粘贴队长的评审意见>

请逐条拆解，每条输出：
- 要求改什么（用一句话复述，确认你理解对了）
- 改哪个文件的哪一部分
- 改完怎么自证（需要什么截图 / 数据 / 链接）

不允许出现「已经修改」「已优化」这种空话；
不允许为了通过检查而删减内容、缩小范围或修改验收标准。
```

---

## 一句话提醒

智能体负责**结构、措辞、查漏**，你负责**事实、判断、签字**。
它写的每一句，你都要能在评审面前讲出来。
