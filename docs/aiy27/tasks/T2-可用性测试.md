# 任务单 T2 — 用户可用性测试

> 派给：薛亦湘（用户验证）
> 建议工期：4 天
> 这份文件的内容整段粘进 GitHub Issue 正文，标题写 `[任务] T2 用户可用性测试 — <你的名字>`

---

## 目标

找 3 位没有参与开发的同学，在不给任何提示的情况下试用产品，记录他们卡在哪里、原话怎么说。这是**唯一能证明「别人用得起来」的证据**，队长自己做不了这件事。

## 前置条件

- [ ] 一台装了本产品的 iPhone（找队长要 TestFlight 邀请，或借用队长的测试机）
- [ ] 3 位被试，不能是三个队员中的任何一个
- [ ] 每位被试愿意被记录原话（口头同意即可，报告里用「被试 A/B/C」匿名）

## 测试方法（照着做，不要临场发挥）

1. 把手机递给被试，只说一句：「这是一个手机上的 AI 助手，你随便用用，帮我看看哪里不好用。」
2. **不要解释、不要提示、不要帮忙操作。** 被试卡住超过 1 分钟就记录「卡住」，然后给最小提示（例如「试试直接说话」），并记录你给了什么提示。
3. 依次给三个任务，每个任务开始前把手机交给他：

| 任务 | 说法（原样念） | 观察重点 |
|---|---|---|
| A | 「让它提醒你明天下午三点交作业」 | 会不会去找日历验证、知不知道要去哪看结果 |
| B | 「问它一道你不会的数学题」 | 会不会用语音或拍照、看不看得懂公式输出 |
| C | 「让它帮你安排这周末的复习计划」 | 多轮对话能不能接上、会不会被复杂指令卡住 |

4. 每个任务记录：是否独立完成、总耗时、卡在第几步、被试说的原话（越具体越好）。
5. 结束后问三个问题并记录回答：
   - 你觉得这个东西最有用的是哪一点？
   - 最让你不放心的是什么？
   - 你会推荐给同学吗？为什么？

## 验收标准

- [ ] 3 位被试，每人 3 个任务，全部有结论
- [ ] 每个任务都有至少一句被试原话（用引号标出）
- [ ] 记录了给了几次提示、提示内容是什么
- [ ] 共性问题 ≥ 3 条
- [ ] 改进建议能对应到具体界面或交互
- [ ] 被试信息匿名化，没有真实姓名

## 必须附带的证据

- [ ] 访谈原始记录（手写拍照或备忘录截图，可打码）
- [ ] 至少 2 张测试现场照片（不拍脸，拍手机和被试的手即可）

## 禁止事项

- [ ] 自己扮演被试
- [ ] 被试是队员本人或家人
- [ ] 让智能体编造原话
- [ ] 只记成功案例、略过失败

## 可以交给智能体做的部分

把所有原始记录发给它，让它：归类共性问题、按出现频率排序、把口语原话保留原样只做归类、起草改进建议初稿。**改进建议你要自己判断合不合理，不合理的删掉。**
