## 1. 为什么重做

v5 在 Keynote 里成立，但用户用 WPS 打开后判定「很丑、很多错误」：整体过平、过散，
像排版练习而不是一份能上台的产品发布稿。v6 不是给 v5 打补丁，而是换一套视觉系统：

- 从「单色象牙纸 + 细线」改为「象牙纸 + 整块深海军蓝分区」，每页都有明确重心；
- 从「原生形状示意」改为「真实设备卡 + 300DPI 真实数据图 + 真实代码面板」；
- 从「英文衬线小标题」改为「超大中文黑体主张 + 英文眉标 + 等宽数据」；
- 先定 10 页的明暗节奏（亮/暗交替），再排每页内容。

同时修掉 WPS 验收暴露的坐标类型 bug（详见第 6 节）。

## 6. WPS 验收链（权威）

本机 LibreOffice 丢全部中文，Keynote 与实际查看器不一致，验收固定走 WPS：

1. `cp docs/aiy27/AIY27-PPT-v6.pptx /tmp/v6-export.pptx`
2. `open -a "WPS Office" /tmp/v6-export.pptx`
3. AppleScript：文件 → `输出为PDF格式...` → `输出为PDF` 窗口点「开始输出」
4. `cp /tmp/v6-export.pdf docs/aiy27/AIY27-PPT-v6.pdf`
5. `swift /tmp/pdfpng.swift docs/aiy27/AIY27-PPT-v6.pdf 1,2,...,10 /tmp/v6`
6. 逐页目检；同时看 2×5 拼图检查整本明暗节奏。

**必须用临时副本导出**：实测 WPS 打开并导出 PDF 后会回写源 PPTX——嵌入约 13MB 字体
（`ppt/fonts/font1.fntdata`），并在本次操作中丢失新加入的背景图与截图。交付文件用
`gen_v6.py` 直接产出的版本（约 1.2MB、12 张媒体），导出前后用 md5 与 `unzip -l | grep media`
核对，避免被 WPS 改写。

本轮修掉的问题：

- 深色分区从纯色矩形改为渐变/光晕/细环背景图，P1 与 P10 的矢量圆环改为烘焙进图，避免 WPS 细线发虚。
- P3 合成代码面板换成真实 VS Code 截图（EngineKit / apps/tool-call / add_calendar_event.json），并保留标题栏、面包屑与投影。
- WPS 导出改为临时副本，避免 WPS 回写源文件时嵌入字体并丢失新图。
- `eyebrow()` 的 `y` 传 float 时未转 `Inches`，所有眉标跑到页顶；改为 `isinstance(y, Length)` 兜底。
- 封面 46pt 标题两行在 WPS 行高比 Keynote 大，副标题与「实验室」重叠；标题保持 46pt，副标题下移到 3.28in，正文/分隔线/三组数字整体下移。
- P3 `code_y` 传 float 导致代码面板贴到页顶并盖住标题；改为 `Inches(4.02)`。
- P5 图注与坐标轴标签重叠；图注下移到 6.40in，主张下移到 6.72in。
- P7 图例压在点阵最后一行；图例下移到 5.90in，分隔线与说明顺延。
- P9 中部过空；改为整幅深蓝「四道闸门」带（2.62–4.72in），HUMAN 闸门用蓝色环 + 圆点，其余为深灰环。
- P10 蓝色圆弧穿过 GitHub 链接；圆下移缩小到 (10.7, 5.2, d=4.2)。
- P6 / P10 页码在深底上用 `kicker(..., dark=True)` 提亮。
- 所有连接线/形状 `shadow.inherit=False`，避免 WPS 主题阴影。
