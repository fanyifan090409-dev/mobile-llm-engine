## 跑分协议

- 负载：固定 300 字短文题（输出必触 256 token 上限），无人值守自动 4 轮；
- 每轮开始前清空对话历史，避免上下文累积拖慢解码；
- 首轮为热身，对外取后三轮稳定值；全程禁自动锁屏；
- 工具类 prompt 不用于跑分（确认弹窗会卡住流程），日历闭环另由 harness 覆盖。

## 结论

1. **Q4_K_M 是手机端速度/内存最优档**：稳定 ~38 tok/s、峰值 <1.9GB，适合作为演示与跑分基准负载；
2. **Q5_K_M 质量优先档**：速度约为 Q4 的 89%，内存多 ~150MB，旗舰质量档定位成立；
3. **Q8_0 不推荐手机日常**：速度约为 Q4 的 71%，峰值 2.72GB，1.7B 在 8GB 机型上余量更紧；
4. **0.6B 适合低内存/轻量场景**：三档 87–97 tok/s、峰值 ~1.1GB，复杂任务质量弱于 1.7B；
5. 跨档连续跑会累积热量，Q8 热态连跑数据（18.1 tok/s）会低估真实性能 —— **16/18 Pro 复跑协议：用 scripts/ios-bench.sh 的冷却参数，档位之间冷却 ≥5 分钟**。
