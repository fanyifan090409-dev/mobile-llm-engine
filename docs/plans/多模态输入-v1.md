# 多模态输入 v1（语音 / 拍照 / 视频抽帧，2026-11-04）

> 定位：**产品层多模态**——所有模态先在本机转成文本，再交给现有 EngineKit + 1.7B 文本模型推理。不做多模态模型训练，不把图片/音频 token 喂给 LLM。
>
> 原则：全部本地、无云端 API；文本链路不动；每个模态独立开关、独立回滚；先做能稳定演示的，VLM 后置。

## 1. 目标与非目标

### 目标

1. **语音闭环**：按住说话 → 本机 VAD/ASR → 可编辑转写 → 1.7B → 本机 TTS 播放。
2. **拍照输入**：相机/相册 → 本机 OCR → 可编辑文本 → 1.7B。
3. **视频输入（P3）**：AVFoundation 抽帧 → YOLO 检测；VLM 只看 3–5 张关键帧，不逐帧跑。

### 非目标

- 不训练/微调 ASR、TTS、VLM；不改变 1.7B 文本模型和 EngineKit 推理接口。
- 不做 always-on 语音、不做云端 fallback、不做手机端“视频大模型”。
- 不把图片/音频直接塞进 LLM 上下文；多模态最终都归一成文本。
- 不在比赛 Demo 主路径放 VLM 视频理解；只作为路线图或 P3 增强。

## 2. 总体架构

```text
麦克风 → AVAudioEngine（16k mono）→ VAD → ASR（sherpa-onnx）
      → 可编辑转写 → DemoModel.send → 1.7B → TTS（sherpa-onnx / Kokoro）→ 扬声器

相机/相册 → Vision OCR → 可编辑文本 → DemoModel.send → 1.7B

视频 → AVAssetReader 抽帧（1 fps + 场景切换，最多 8 帧）
     → YOLO（Core ML）检测 / VLM 关键帧描述 → 结构化文本 → DemoModel.send
```

**核心约束**：1.7B 文本模型是唯一推理核心；ASR/TTS/OCR/YOLO 都只是“输入/输出适配器”。这样文本链路、工具调用、跑分、Harness 全部不受影响。

## 3. 技术选型

| 能力 | 选型 | 现成资产 |
|---|---|---|
| ASR | **sherpa-onnx 2.0.1**（中文 Zipformer / Paraformer） | 官方 SPM 包 + `ios-swiftui/SherpaOnnxAsr` 示例（AVAudioEngine + 16k 转换 + 流式识别） |
| TTS | **Kokoro 82M int8 multi-lang v1_1** | 官方 `swift-api-examples/tts-kokoro-zh-en-lexicon.swift` + `SherpaOnnxTtsPhonemize` 示例 |
| VAD | sherpa-onnx Silero VAD | 同包，不额外引库 |
| OCR | Apple Vision `VNRecognizeTextRequest` | 系统框架，无模型文件；中英双语、`.accurate` |
| 视频抽帧 | AVFoundation `AVAssetReader` / `AVAssetImageGenerator` | 系统框架；1 fps + 场景切换 + 最多 8 帧 |
| 检测 | **YOLOX（Apache 2.0）/ Create ML** | **不要用 Ultralytics YOLO**：`ultralytics/yolo-ios-app` 与 YOLOv5/v8/11 权重是 AGPL-3.0，闭源分发/上架会触发源码开放义务 |
| 关键帧描述 | 小 VLM + llama.cpp `mmproj` | P3 可选；与 1.7B 互斥驻留，不进 MVP |

**现成组件复用清单（GitHub 已核对，2026-11-04）**

- `k2-fsa/sherpa-onnx`：15.7k stars，Apache 2.0，最新 v2.0.1（2026-10-26）。官方 `Package.swift` 支持 iOS 15+，提供 `sherpa-onnx`（静态 XCFramework，推荐）和 `sherpa-onnx-shared` 两个 product；Xcode 直接 Add Package，无需自己编 C++。
- 官方 iOS 示例：`ios-swiftui/SherpaOnnxAsr`（麦克风流式 ASR，含 AVAudioEngine 重采样）、`ios-swiftui/SherpaOnnxTtsPhonemize`（TTS 播放）、`swift-api-examples/tts-kokoro-zh-en-lexicon.swift`（Kokoro 中英混读）。
- 模型：`sherpa-onnx-streaming-zipformer-small-bilingual-zh-en-2023-02-16`（压缩包 458MB；POC 可先用 `streaming-zipformer-zh-14M` 74MB）；`kokoro-int8-multi-lang-v1_1`（压缩包 147MB，103 音色，中英）。
- `ggml-org/whisper.cpp`：MIT，54.9k stars，有 iOS 示例；只作 sherpa-onnx 不达标时的备选，不双栈。
- 不采用第三方 `sherpa-onnx-spm` 镜像（只有 3 stars、非官方）；直接用官方包。

**选型纪律**

- 音频只保留 sherpa-onnx 一条运行时：ASR、VAD、TTS 同包；不要同时上 whisper.cpp。
- Kokoro 是模型，sherpa-onnx 是运行时。Kokoro v1_1 int8 先试；中文音色/韵律不达标就换 `vits-melo-tts-zh_en` 或 VITS 中文，仍走同一包。
- 模型许可证上线前逐个核对：sherpa-onnx（Apache 2.0）已明确；Kokoro 权重原始为 Apache 2.0，但 v1_1 多语言包的音色来源与 ASR 训练数据许可要再看包内 LICENSE；YOLO 的 AGPL 风险已排除。

## 4. 交互设计

### 语音

- 输入栏左侧加麦克风按钮；**按住说话**（MVP 不做 always-on），松手结束。
- 录音时显示计时和波形；最长 30 秒，最短 0.5 秒。
- 结束后显示“识别中”，然后弹出**可编辑转写**：
  - 主按钮“发送给 Agent”；
  - 次按钮“重说”/“取消”；
  - 默认不自动发送，避免 ASR 错字直接进模型。
- 回答气泡带扬声器按钮：可重播/停止；语音发起的轮次默认自动播报，打字轮次默认不播报。
- 工具调用路径不变：转写文本仍走 `looksLikeCalendarRequest` 决定是否挂日历工具。

### 拍照

- 输入栏加相机按钮；`拍照` / `从相册选择`。
- 图片缩放、转正后跑 Vision OCR；确认页显示缩略图 + 可编辑文字 + “识别可能有误”。
- 发送时提示词前缀：“下面是我从照片里识别出的题目，可能有误；请先复述题目，再解答。”
- 消息气泡显示缩略图（512px，仅内存），原图 OCR 后释放。

### 视频（P3）

- 从相册选视频；抽帧后显示 8 张缩略图。
- YOLO 检测结果汇总成结构化文本（“第 1/4/7 帧检测到 person，置信度…”），再交给 1.7B 解读。
- VLM 只在 3–5 张关键帧上跑，且与文本 LLM 互斥；比赛 Demo 默认不启用。

### 错误态

- 无麦克风权限 → 设置入口；无相机权限 → 设置入口。
- 没识别到语音/文字 → 提示重说/重拍，不发送空内容。
- 模型文件缺失/校验失败 → 引导到“模型库”下载，不崩溃。
- ASR/TTS 初始化失败 → 保留文本输入，语音入口置灰并说明原因。

## 5. 模型与内存预算

| 模块 | 模型包/近似内存 | 说明 |
|---|---:|---|
| 1.7B Q4_K_M 文本 | 1.28 GB 权重 | 4K 峰值约 1.9 GB；8K 峰值约 2.4 GB（现有实测口径） |
| ASR（streaming Zipformer small bilingual） | 压缩包 458 MB | 中文+英文；POC 可换 `streaming-zipformer-zh-14M`（74MB）先跑通，再按准确率决定 |
| TTS（Kokoro int8 multi-lang v1_1） | 压缩包 147 MB / 实测 432MB | 103 音色，中英混读；初始化 0.44s，生成 0.3–1.0s |
| VITS 中文（备选） | 约 100–200 MB | Kokoro 中文不达标时替换 |
| YOLOX / Create ML 检测 | 0.01–0.05 GB | P3；不用 Ultralytics AGPL |
| VLM 2B Q4 + 视觉编码器 | 2.5–3.5 GB | 不与 1.7B 同时驻留 |

**驻留策略**

- 1.7B 常驻；ASR 只在录音/转写时加载，TTS 只在播报时加载，用完释放。
- 切模态前先释放上一个模态模型；VLM 与 1.7B 互斥，用完卸载再回文本。
- 8GB 机型语音轮次默认 4K 上下文；12GB 可用 8K。目标峰值：8GB ≤2.8GB，12GB ≤3.5GB。
- 图片 OCR 前缩到最长边 2048px；视频最多 8 帧，单帧最长边 640px（YOLO）/ 448px（VLM）。

## 6. 代码落点

新增 `apps/ios-shell/Sources/Modality/`：

- `AudioCapture.swift`：AVAudioEngine、16k mono 转换、录音权限、音频会话。
- `SpeechRecognizer.swift`：sherpa-onnx ASR 封装；VAD 分段；返回转写和置信度。
- `SpeechSynthesizer.swift`：Kokoro/VITS TTS 封装；`AVAudioPlayerNode` 播放/停止。
- `PhotoOCR.swift`：Vision OCR、图片缩放/转正、空结果处理。
- `VideoFrames.swift`：AVAssetReader 抽帧、场景切换、帧数上限。
- `ModalityCoordinator.swift`：模态状态机（idle/listening/thinking/speaking），负责模型加载/释放顺序。
- `ModalityModelStore.swift`：模型文件下载、SHA-256 校验、版本与删除。

修改：

- `DemoChatView.swift`：麦克风/相机按钮、录音浮层、转写确认页、拍照确认页、消息缩略图、播报控制。
- `DemoModel.send`：增加 `source: .text/.voice/.photo/.video`，用于提示词前缀和 UI；`usesTools` 路由不变。
- `DemoHarness.swift`：新增自检（ASR/TTS/OCR/帧提取），目标 16/16。
- `project.pbxproj`：`NSMicrophoneUsageDescription`、`NSCameraUsageDescription`；通过 SPM 加 `sherpa-onnx` 2.0.1（静态 product），不手工拖 XCFramework。
- 模型库页：增加“语音与视觉模型”区，显示大小/状态/删除。

不改：`engine/`（EngineKit）、文本模型、工具调用、跑分与现有 13 条 Harness。

## 7. 阶段与时间

### P0 技术验证（3–5 天，先做）

> 进度（2026-11-04 07:56）：P0-0 完成——官方 SPM 2.0.1 解析通过，app arm64 编译成功，`nm` 确认 `SherpaOnnx` 符号已链接。P0-1 完成——真机 TTS：Kokoro int8 v1_1 生成「你好，我是本地 Agent」1.89 秒音频（24kHz，45360 samples，WAV 非静音），初始化 0.44 秒，生成 0.32–0.98 秒，**峰值内存 432MB**；真机 ASR：streaming Zipformer zh 14M 对内置 5.6 秒中文音频识别为完整句子，**内存 73MB**；包体增加 **38MB**（578MB vs 540MB）。TTS 432MB 超原定 300MB 门禁，但 1.7B 文本 + 4K 上下文（1.9GB）合计约 2.33GB，8GB 机型可控；VITS melo 中文模型 176MB fp32，不是明显的内存更优解，暂保留 Kokoro。待测：实时麦克风（需用户点按钮说话）。

- **P0-0 依赖接入**：Xcode 加官方 `https://github.com/k2-fsa/sherpa-onnx` 包，版本精确 `2.0.1`，选静态 product `sherpa-onnx`；先只 `import SherpaOnnx` 编译通过，不改业务代码。
- **P0-1 官方示例对拍**：跑 `ios-swiftui/SherpaOnnxAsr` 和 `SherpaOnnxTtsPhonemize`，用官方示例验证模型和 iPhone 音频链路；再照 `tts-kokoro-zh-en-lexicon.swift` 把 TTS 配置换成 `kokoro-int8-multi-lang-v1_1`。
- **P0-2 指标**：中文 ASR 一段 5 秒音频、TTS 一句“你好，我是本地 Agent”；测初始化时间、首字延迟、峰值内存、包体增量、后台/中断恢复。
- **P0-3 决策**：ASR 用 `streaming-zipformer-small-bilingual` 还是 `streaming-zipformer-zh-14M`；TTS 用 Kokoro v1_1 还是 VITS 中文。
- **门禁**：ASR 10 条短句可用 ≥8 条；TTS 可听、可停止；ASR 峰值 <300MB（实测 73MB），TTS 峰值 <450MB（实测 432MB）；不崩溃。TTS 超 450MB 或音色不可接受则换 VITS 中文；再不行降级 Apple Speech + AVSpeechSynthesizer，或只做拍照。

### P1 语音闭环（5–8 天）

> 进度（2026-11-04 08:16）：代码链路完成——`VoiceService` 统一封装 ASR/TTS 与音频会话；聊天页加麦克风按钮、录音横幅、可编辑转写确认页、语音轮次自动播报、助手气泡重播/停止按钮。Harness 新增 `voice-models`、`voice-tts-synth`、`voice-asr-roundtrip` 三条自检，真机 **16/16 全绿**：TTS 合成 2.36 秒 24kHz 音频，回环 ASR 转写「明天下午三点我开会」（关键信息命中）。待用户真机手测实时麦克风与 TTS 可听性；音频中断/路由切换尚未做专门用例。

- 按住说话、转写确认、发送、TTS 播报、停止/重播。

- 真机验收 + Harness 自检。

## 9. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 三套运行时集成（llama.cpp + ONNX + Core ML） | 高 | P0 先验证；官方 SPM 包钉 2.0.1；能单栈就单栈 |
| 中文 ASR 噪声场景 | 中 | 近讲 + VAD + 可编辑转写；Demo 用安静环境 |
| Kokoro 中文音色不达标 | 中 | 换 `vits-melo-tts-zh_en` 或 VITS 中文，仍走 sherpa-onnx；不新增运行时 |
| 内存/热控 | 中 | 按需加载、用完释放；8GB 用 4K；VLM 不进 MVP |
| 音频会话/回声/打断 | 中 | MVP 按住说话；`.voiceChat` 模式；先不做 always-on |
| 包体/下载 | 中 | 模型作为数据下载，SHA-256 校验；不下载可执行代码；ASR+TTS 约 600MB 压缩包，按需下载 |
| **YOLO 许可证** | **高** | **Ultralytics YOLO/v5/v8/11 是 AGPL-3.0，不上架分发；P3 改用 YOLOX（Apache 2.0）或 Create ML** |
| App Store 权限/隐私 | 低 | 麦克风/相机文案；隐私政策写清本地处理 |
| 赛程冲突 | 中 | MVP 冻结；P3 只做路线图 |

**回滚**

- `UserDefaults` 开关：`enableVoice` / `enablePhoto` / `enableVideo`，默认关闭，验证通过再逐项打开。
- 模态代码独立目录；文本链路零改动；删模型文件即可回收空间。
- P0 失败：退回 Apple 本机 Speech + AVSpeechSynthesizer 做演示，或只保留拍照 OCR；不阻塞文本主线。
