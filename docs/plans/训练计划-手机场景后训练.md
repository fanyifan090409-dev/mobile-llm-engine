## 一、训练目标与产品绑定

- 模型库首发 **3 个，必须全部是我们训练过的**（用户拍板）：对应内存三档——0.6B 兜底 / 1.7B 主力 / 4B 旗舰；
- **训练画像 = 手机用户高频需求**（用户拍板）：翻译、实时记录整理、日程提醒、消息文案、摘要检索；**明确不做**：编程/项目类任务；
- 边界：不做 ASR（语音转写用手机系统能力），我们做「转写文本的整理/总结/要点提炼」；不做长文档处理（手机场景短平快）；
- 硬约束：保留 Qwen3 原生 chat template（保证 GGUF 推理兼容）；产出 Apache 2.0 可商用。

## 二、三模型分工与算力预算

| 档位 | 底座 | 续训 tokens | SFT 数据 | 预计 GPU 时间 | 手机定位 |
|---|---|---|---|---|---|
| 0.6B | Qwen3-0.6B | 2B | 首轮共用 ~10M | ≈1-2 天 | 低端机：翻译、简单整理 |
| 1.7B | Qwen3-1.7B | 5B | 首轮共用 ~10M | ≈3 天 | 主力：全任务 + 工具调用 |
| 4B | Qwen3-4B | 5-10B | 首轮共用 ~10M | ≈1-2 周 | 旗舰：多轮 agent、复杂整理 |

**SFT 量修正（2026-10-23）**：原设想每模型 100-200M SFT tokens，但双 teacher 合成产能约 100-200 tok/s（实测首小时 374 tok/s 含输入 token 折算后有效输出约 150 tok/s），1-2 天窗口只能出 ~10M。定为首轮共用 10M（三模型同源数据集），训练后按评测结果决定是否二轮扩量/换云端 teacher。

（算力折算按双卡 838 TFLOPS 理论、25-35% MFU，见调研文档第十节。）

## 三、数据策略（真正的墙：不在算力，在数据）

### 任务画像与占比（设想初稿，可调）

1. **翻译 25%**：中英互译、口语短句、截图文本；
2. **实时记录整理 25%**：转写文本 → 要点/纪要/行动项；
3. **日程与提醒 20%**：自然语言 → 结构化事件（带工具调用轨迹）；
4. **消息与文案 15%**：草稿、语气改写、缩写扩写；
5. **摘要与检索 10%**：短文/网页/笔记问答；
6. **其他手机场景 5%**：单位换算、时间计算、本地信息查询。

### 合成管线（已拍板走 A，2026-10-23 执行中）

- 质检：qc_sft.py（分类计数/长度分布/去重率/工具调用解析率 + 抽样打印）；抽样人工检查由我在合成后执行；
- **首轮结果与翻译补充（2026-10-23）**：首轮 10.0M tokens / 43,104 样本（21:09），QC 通过。类别占比偏移：translate 仅 3,481 条（~1.6% tokens，计划 25%），根因是翻译样本短（~30 tokens/条）+ 种子池仅 48 句被去重吞。补充轮 synth_translate_supp.py（23:13 完成）实得 80,000 条 / 4.6M tokens（超预期，样本 ~57 tokens/条），translate 合计 83,481 条。**拼装时处理**：translate 降采样回 25% 左右；misc（10,262 条，一次调用出 5 条致样本虚高）降采样到 5%；
- **message 类选项式回答问题（2026-10-24 处置）**：首轮 5,088 条 message 样本中 1,542 条（30%）是「给你几个选项」式回答（与「帮我写一条消息」意图不符，会让模型学会多选项模板）。原计划加一轮修正合成（synth_message_fix.py，强制单条草稿），但 23:30 定时任务按既定条件已把 teacher 全部下线（23:31 记录），修正轮启动时端口已关、空转即停。**处置**：不重启 teacher（重启+修正+再下线约 1.5h，message 草稿是底座强项），拼装时用规则过滤（选项式 + markdown 模板样「###/**」+ 「这里」开头），实际过滤 2,540 条，保留 2,548 条 / 0.13M tokens（占比 ~1.5%，原计划 15%，接受偏差并在评测中重点验证消息文案质量；用户可随时要求重启 teacher 补一轮或走云端 API）；

- **续训语料（2026-10-24 定案并完成打包）**：`fineweb-2` 中文子集 `cmn_Hani`（370 分片共 1.6TB，取前 10 分片约 46GB，全量预算 12-17B tokens 够用）+ `BelleGroup/train_3.5M_CN`（对话增味）。0.6B 分配：BELLE 250M + fineweb2 1.95B = 2.2B tokens，已打包为 data/pt/belle.bin + fw2.bin（uint32 memmap，eos 分隔）。HF 直连被墙，全部走 hf-mirror；
- 合规：全开源 + 自合成，PIPL 纪律（不采集用户真实数据）。

## 四、训练方案（技术设想）

- 框架：HF transformers + DeepSpeed ZeRO-3（4B：ZeRO-3 + 优化器 offload 到 128GB RAM）；BF16 默认，Blackwell FP8 可选试（支持成熟再上）；
- 超参初稿：lr 1e-5 余弦衰减、warmup 3%（transformers 5.x 已移除 warmup_ratio → 折算 warmup_steps）、序列 2048（手机场景不需要长序列；实测 4096 不比 2048 快且更吃显存）、梯度累积补 micro-batch、epoch 1-2；
- SFT：1.7B 全参；4B LoRA（r=64/α=128）或 ZeRO-3 全参（显存实测定）；chat template 保持 Qwen3 原样；
- 工程纪律（沿用旧项目惯例）：MLflow（:5000）记录所有 run；每 500-1000 step checkpoint；看护脚本防跑飞/掉卡/过热；训练日志进 lab-notebook（YYYY-MM-DD- 前缀）；
- 备份：改动前备份到 /home/ubuntu/backups/（训练机 AGENTS.md 铁律）。

## 八、风险与回滚

- 续训灾难性遗忘 → 回退纯 SFT/LoRA 变体；对拍不过先发官方模型占位，自训达标后替换；
- 4B 全参 OOM → ZeRO-3 + CPU offload 预案（慢 30-50% 可接受）；
- 训练中断 → checkpoint 续训（resume 路径事先写入启动脚本）；
- 磁盘：**实测 /home/ubuntu 仅 463GB 余量**（2026-10-23 df -h）。预算重算：数据 ~0.1GB、三模型 checkpoint 滚动保留 2-3 个 ≈ 150-250GB、量化产物 ~10GB → 463GB 可用但不宽裕；训练前清点，必要时清理旧项目大文件（先备份）或缩减 ckpt 保留数；
