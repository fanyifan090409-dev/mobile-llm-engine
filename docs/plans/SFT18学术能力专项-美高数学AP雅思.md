## 2. 数据设计

### 2.1 类别与形态（三类学术任务）

| 类别 | 任务形态（训练轨迹的 user → assistant） | 拟合成量 |
|---|---|---|
| ap_calc 微积分 | 出题（给定知识点/难度，产出题目+答案+解答步骤）；解题（用户给题，模型给解答步骤） | ~35% |
| ap_stats 统计 | 同上（概率/假设检验/置信区间/抽样分布） | ~25% |
| ielts 雅思 | 写作：题目+范文+评分维度点评；阅读：文章+题型+答案详解；听力：听力文本+题目+解析 | ~40% |

### 2.2 量级（加训轮数据）

- 总量：**约 30,000-40,000 条 / 6-8M tokens**（参照 SFT3B 专项的 47,290 条/7.13M 量级；1.7B 参数更大可多喂，两个模型共用同一批数据）
- 加训轮占比：**学术 70-80% + 历史池五类样本 20-30%**（防灾难性遗忘，SFT3B 先例：专项占比调高但保留其他类）
- 合成去重 QC 沿用 qc_sft.py（schedule XML 解析等检查不适用，学术类检查：题目-答案配对完整性、公式不残缺、解答步骤非空）；已新增 202X/XXXX 占位符检查，出现即 QC 不过（exit 1）

### 2.3 教师分配

- **ap_calc / ap_stats** → 30B-A3B（:8003，coder 血统、数学推理稳）
- **ielts** → 27B（:8002，长文本生成快）；30B 空闲时也可分担
- **补充通道（2026-11-02 用户新增）**：Pro 机官方 CodeBuddy CLI（云端大模型）跑高质量补充批次（train/synthesize/synth_cloud.py，复用同一构建器与校验契约），产物与训练机 teacher 输出按 hash 去重合并
- 合成请求统一 `enable_thinking=false`（现有合成脚本已固定）

### 2.3b 雅思写作风格契约（2026-11-02 用户拍板）

- 目标：**高质量 + 低 AI 检测率 + 符合亚洲（中国）考生真人写作风格**，band 7.5-8 水准，不是范文腔
- 结构自然：开头直入主题不背模板套句，主体两段论证，结尾自然收束
- 词汇学术常用即可不堆砌生僻词；句式长短结合，允许少量真人不完美（个别搭配略生硬、偶见中式思维痕迹），整体连贯、论证扎实
- 严禁 AI 特征表达：delve / pivotal / paramount / multifaceted / tapestry / a double-edged sword / It is widely acknowledged / In today's society / Moreover-Furthermore-Additionally 连发 / Firstly-Secondly-Finally 死板框架 / 每段 In conclusion 收尾
- 已固化进 synthesize_academic.py 的 `IELTS_STYLE`（训练机 teacher 与 Pro 云端两条合成链共用）；2026-11-02 之前合成的旧风格 ielts 样本已作废重产

### 2.4 混入真题（等用户材料）

- 用户提供学校真题/讲义（PDF/Word/图片）→ 本机加工：文本提取 → 切题 → 按 2.1 形态转成 Qwen3 聊天模板轨迹
- 加工脚本新增（train/synthesize/ 下，等材料到位再写）
- 备注：真题仅用于训练，不进入公开发布的数据集；模型权重本身不含原文存储

### 2.5 幻觉率三修复（2026-11-02 已落地，SFT17 评测报告结论）

### 3.2 训练机资源时序


### 3.3 防遗忘守卫

- 加训前先跑原版 15 题画像评测留基线；加训后重跑，要求不掉档（PASS 维持 PASS）
- 学术类评测（见 §4）达标线：AP 解题正确率、雅思范文质量抽检

## 4. 评测设计

| 维度 | 方法 | 达标线 |
|---|---|---|
| AP 微积分/统计解题 | 合成期留出 holdout 题（不进训练集），两个模型作答，规则+人工抽检 | 正确率 ≥ 60%（0.6B）/ ≥ 70%（1.7B） |
| 雅思写作 | 生成范文，按任务回应/连贯/词汇/语法四维抽检 | 无明显离题与结构崩溃 |
| 雅思阅读/听力 | 给定文章/文本出题或作答，关键词覆盖检查 | 题型-答案对应关系成立 |
| 画像防遗忘 | 现有 15 题通用评测重跑 | 不降档 |

## 5. 风险与回滚点

| 风险 | 对策 |
|---|---|
| 学术数据把五类画像冲掉（灾难性遗忘） | §3.3 守卫 + 历史池 20-30% 混合 |
| 0.6B 数学推理天花板（解题正确率上不去） | 达标线分档（0.6B 60%）；不达标则学术能力以 1.7B 为主推，0.6B 保留出题类简单形态 |
| 真题材料迟迟不到位 | 不阻塞：合成为主线，真题到一批混一批（二次加训或并入 4B 时代） |
| teacher 合成期 GPU 与 SFT 训练争卡 | 合成先于训练，串行执行，不并行 |
| 公式/数学符号在 GGUF 分词与生成中残缺 | 合成模板约定：公式用 LaTeX 纯文本或 Unicode 数学符号，避免依赖渲染 |

**回滚点**：①合成 QC 不过 → 重跑合成；②加训后画像评测掉档 → 回退 SFT3B/SFT17 权重，学术数据修正后重训；③每次训练前备份起点权重到 /home/ubuntu/backups/（训练机铁律）。
