# 续训配方教学：为什么我们的「平台期」是假的

> 写给 Elthan 的教学版。不预设你懂训练，从零讲。目标：看完能回答「为什么必须继续训练」「接下来怎么训」。

## 一、先回顾：我们遇到了什么

0.6B 模型续训 2B tokens 后，loss 从 3.95 降到 3.17，最后 150 步基本不动了（3.161 → 3.159 → 3.157）。我当时判断「平台期，数据吃饱了」。

**这个判断只对了一半。** 原因在下面第三节。先说结论：loss 不动，很大一部分不是因为「模型学够了」，而是因为「学习率自己把自己关掉了」。

## 二、知识的两个来源：GitHub 仓库 vs 论文（你要的分辨方法）

这个领域的知识有两个产地，性质完全不同：

| | GitHub 仓库（TinyLlama、SmolLM、MobileLLM 官方） | 论文（ICML/NeurIPS/TMLR 等正式发表） |
|---|---|---|
| 是什么 | 别人训练时**实际用的配置**，原样公开 | 别人做了**对照实验**之后写的论证 |
| 优势 | 可复跑：lr、batch、数据量全部具体到数字，照着跑就能复现 | 有依据：每个选择都有消融实验（改一个变量看效果），告诉你**为什么** |
| 劣势 | 没有「为什么」：lr 为什么是 4e-4 不是 2e-4？没有对照实验 | 配置常缺细节：比如 Qwen3 技术报告不给 0.6B 的具体 lr/batch |
| 类比 | 菜谱：照着做能出锅 | 食品科学论文：告诉你为什么这个火候 |

**文刊（正式发表）和 arXiv（预印本）的区别**：arXiv 是「贴出来给大家看」，没经过同行评审，可能被拒稿、被撤回、有错误没人管；正式发表（ICML/NeurIPS/ACL/EMNLP/TMLR 等）是评审人审过、作者改过、会议收了的版本。所以这次调研的规则是：**正式发表优先，arXiv 只做补充并标注**。

**怎么用**：论文定「原则」（调度长什么样、要不要 replay），仓库定「具体数字起点」。这次调研给我们的配方就是这么合出来的。

## 三、核心概念教学：为什么平台期是假的

### 1. 学习率（lr）是什么

训练时每一步「学多少」的旋钮。lr 大 = 步子大，学得快但容易踩坏已经学会的东西；lr 小 = 步子小，稳但学得慢。

### 2. cosine 调度：我们上一轮用的

cosine 调度 = **从训练开始就计划好什么时候关旋钮**：lr 从峰值一路平滑降到接近 0，训练结束时正好关死。

我们的 2B tokens 计划就是 cosine。结果：**最后阶段 lr 已经衰减到 ~0**。这时 loss 不再下降，有两种解释：

- A. 模型真的学够了（数据饱和）
- B. 旋钮已经关了，模型想学也动不了（**人为饱和**）

我之前只报了 A，没强调 B。调研里多处证据（MiniCPM 的 WSD 论文、Infinite LR 论文）都指向：**cosine 的末尾平台期很大程度是 B**。0.6B 模型在 MobileLLM 的论文里 1T tokens 还在降 loss——我们才喂了 2B，远远没到「吃不下」的量。

这就是「错误平台期」的含义：**不是模型不行了，是调度把模型按住了**。

### 3. 正确做法：WSD 调度（MiniCPM，COLM 2024 正式发表）

WSD = Warmup（预热）- Stable（稳定）- Decay（衰减）：

- **预热**：起步 lr 从 0 爬到峰值（几百到一千步），防止开头步子太大踩坏
- **稳定**：长时间保持峰值 lr 不动——这是模型真正学东西的阶段，占 85% 左右
- **衰减**：最后 10-15% 把 lr 线性降到接近 0，收尾定型

和 cosine 的关键区别：**稳定期 lr 一直开着**，不会提前关旋钮。loss 曲线会一直缓慢下降，直到衰减段才快速俯冲收尾。

还有一个更激进的版本叫「无限 lr 调度」（arXiv 2503.02844，仅预印本）：恒定 lr + 60% 衰减，专门为「续训续训再续训」设计——每次续训不用重新预热（重新预热反而伤模型）。我们这次用 WSD，因为它更主流、有正式发表依据，且随时可以再续一段。

### 4. 续训的另一个坑：遗忘（forgetting）

继续训练新数据，模型会**忘掉旧东西**（比如之前 2B tokens 学的、还有 Qwen3 原厂的知识）。正式发表的解决方案（Ibrahim et al., TMLR 2024）：

- 续训时**掺 1% 左右已经训过的旧数据**做「复习」（replay）
- lr 不要开得太大（比首次预训练峰值低一档）

复习的比例他们试过 0.5%~10%，1% 就够明显抗遗忘。

### 5. 数据配比

小模型比大模型更需要「精选数据」：

- **中文为主**：我们的目标用户是中文日常任务（CT-LLM 用中文:英文=2:1）
- **网页打底、代码数学提能力**：SmolLM2 末段配比 74% 网页 / 16% 代码 / 10% 数学（arXiv 仅预印本，但被广泛复现）
- **退火期（衰减段）上采样高质量数据**：最后 10% 喂好数据，效果堪比全程喂好数据

## 四、我们的配方（论文定原则 + 仓库定数字）

调研确认的关键数字依据：
- MobileLLM（ICML 2024 正式发表）：小模型「深度优先」、1T tokens 还在降 loss
- MiniCPM（COLM 2024）：WSD 调度形态
- Ibrahim et al.（TMLR 2024）：续训 re-warmup 有害 + 1% replay 抗遗忘
- SmolLM 仓库：batch 2M tokens、seq 4096 量级的工程参数
- TinyLlama 仓库：lr 4e-4 起步的工程参数

**0.6B 续训配方（草案）**：

| 参数 | 值 | 理由 |
|---|---|---|
| 调度 | WSD（预热 500 步 → 稳定 85% → 线性衰减到峰值 1/20） | MiniCPM；躲开 cosine 人为饱和 |
| 峰值 lr | 2e-4 | 低于 Qwen3 原预训练峰值、高于上次 SFT 量级；续训「学得进 vs 忘得少」平衡点 |
| batch | 全局 ~1M tokens（seq 4096 × 双卡各 128 × 累积） | SmolLM2 同量级；双卡 5090 显存够 |
| 数据 | 中文网页 ~50% + 英文高质量 ~20% + 代码 ~15% + 数学 ~10%；掺 1-5% 已训 2B tokens 旧数据 replay | CT-LLM 中英比 + SmolLM2 配比 + TMLR 2024 replay |
| 续训量 | 先 2B tokens 观察曲线，仍降则续 2-5B | MobileLLM：0.6B 吃 4-8B 不算过度训练 |
| 数据来源 | 已下载的 fineweb-2 中文（cmn_Hani 前 10 片 44GB）+ BELLE 3.5M 对话 | 本地已有，不用重新下载 |

## 五、大白话总结

1. 上一轮「平台期」主要是 **cosine 调度提前关旋钮**造成的假象，不是模型吃饱了——所以**必须继续训练**（你拍板的方向是对的，有论文撑腰）。
2. 这次用 **WSD 调度**：长时间保持 lr 开着，最后才收尾；loss 会一直慢慢降。
3. 掺 **1% 旧数据复习**，防止忘掉已学的。
4. 先训 2B 看曲线，好就继续加到 4-8B。
